# 终端渲染性能与内存优化报告（2026-09-06）

## 背景

DeepTerm 的终端渲染管线（`TerminalElement`）此前已具备 alacritty damage API 的
行级追踪与逐行 shape 缓存，本次工作在此之上完成了两项优化（O1/O2）与一项容量
量化（O3），并为全部结论建立了可复现的测量设施。

- 测量环境：macOS 25.4.0 arm64（Apple Silicon），nightly rustc，gpui rev ac099b4
  `#[gpui::bench]`（真实 CoreText 排版 + 无头 Metal 渲染提交）。
- 基线代码：`74fcd6c`（git worktree 检出 + 测量脚手架，脚手架不参与被测路径）。
- 交替测量：before/after 在同一负载窗口内交替各跑 3 轮，取中位数 ——
  抵消 72 天未重启机器上的后台负载漂移。
- 复现：
  - `cargo bench --bench terminal_render`
  - `cargo test terminal_memory -- --nocapture`（内存数据打印到测试日志）

## 优化内容

### O1 选区计算快速路径

拖拽选择时每个 mouse-move 都会推进选区，渲染帧需要为**整个视口**计算选区高亮。
旧实现对每行逐格调用 `SelectionRange::contains`（约 `cols × rows` 次，160×40
视口即 6400 次调用/帧）并构建 `Vec<usize>`，且选区每变一次即失效全部行缓存。

新实现 [`selection_spans_for_row`](../src/terminal_view/terminal_element.rs) 以
O(1) 算术区间求交直接产出合并后的高亮 span：

- Simple/Semantic/Lines（`is_block=false`）：中间行整行、首行 `[start.col, 行尾]`、
  尾行 `[0, end.col]`；单行选区 `[start.col, end.col]`。
- Block：每个相交行取相同列区间。
- 行缓存字段从 `selection_cols: Vec<usize>` 改为直接存
  `selection_spans: Vec<BackgroundSpan>`（quad 段），删除了逐格扫描的增量更新路径
  （`update_selected_cols_in_range`）—— O(1) 全量重算比增量路径更便宜。

**正确性证据**：600 组随机案例（随机网格行 × 随机选区端点 × block/非 block ×
越界列）的随机平价测试
[`selection_spans_parity_fast_path_matches_per_cell_scan`](../src/terminal_view/terminal_element.rs)，
逐格 `contains` 参考实现与新快速路径输出完全一致。该测试**在落地前抓到**
一起点列越界（`start.column > 行宽`）时错误截断、伪造行尾 span 的真实 bug。

### O2 消除 FlattenedRenderCache 双份存储与每帧全量重建

旧实现在行缓存之外维护一份 `FlattenedRenderCache`（全视口 runs/盒字符/背景/选区
四个 `Arc<[…]>` 拷贝）：任何一行 dirty / 选区 / 悬停变化都会把**所有行**的数据
重新 extend 进四个新 Vec 并重新分配 Arc —— 与行缓存重复存储，且每帧 O(视口) 次分配。

新实现：

- `PrepaintState` 直接以所有权持有 `Vec<RowRenderCache>`（take/restore 模式，
  与既有的 scratch 缓冲一致），行缓存即唯一数据源。
- paint 按行序遍历（行内顺序保持 Zed 层级：背景 → 选区 → 文本 → 盒字符；跨行
  区域互不重叠，行序输出与全局分层视觉等价），结束时把行缓存归还视图。
- `FlattenedRenderCache` 缩为「缓存签名」（排版度量 + 悬停链接），仅用于失效判定。

**分配证据**（`cargo test terminal_view_prepaint -- --nocapture`，单行 dirty 帧）：

| | 分配次数 | 分配字节 |
|---|---|---|
| 优化前 | 1932 次 | 8.1 MB |
| 优化后 | 44 次 | ≈0 |
| **变化** | **-97.7%** | **≈-100%** |

（稳态帧 55 次分配为 draw 框架常量与光标块字符 shape，两版持平。）

### O3 滚动缓冲的量化（保持固定 10000 行）

scrollback 固定 10000 行是单终端内存的最大项。实测（`phys_footprint`，
80 列默认网格）：

| scrollback | 实测增量 | 每千行 |
|---|---|---|
| 1 000 行 | ≈1.8–6 MB* | ≈1.8–6 MB |
| 10 000 行 | ≈14–16 MB | ≈1.4–1.6 MB |

*footprint 受相邻实体释放时机影响有波动，量级稳定。

结论：10000 行默认值即 ≈15 MB/终端的占用来源，量级已量化。产品决策保持
固定 10000 行不变（不引入设置项）；`Terminal::new_headless` 保留参数化入口，
测量设施可随时复验其他容量的占用曲线。

## 渲染性能：交替基准结果（中位数，3 轮）

| 场景 | 基线（中位） | 优化后（中位） | 变化 |
|---|---|---|---|
| 全行 dirty（批量输出，40 行/帧） | 3684 µs | 3255 µs | **-11.6%** |
| 单行 dirty（回显/打字） | 1471 µs | 1112 µs | **-24.4%** |
| 无 damage（光标闪烁） | 1221 µs | 1062 µs | **-13.0%** |
| 滚动一行 | 2394 µs | 1864 µs | **-22.2%** |
| 拖拽选区一步 | 1546 µs | 1420 µs | **-8.1%** |

测量方法：两组二进制（基线 = `74fcd6c` + 纯测量脚手架；优化后 = 当前工作区）
在相同负载窗口内交替运行，每侧 6 组采样取中位数。单轮绝对值随系统负载漂移
±30%（本机 72 天未重启、后台负载 3–8），交替取中位数可消除趋势性漂移；
6 组原始数据（µs）：

```
全行 dirty     B=[2309, 3175, 3253, 4114, 4916, 7868]  A=[2155, 2635, 3091, 3420, 4515, 5044]
单行 dirty     B=[ 673, 1328, 1455, 1488, 1528, 2023]  A=[ 539,  733,  901, 1324, 1552, 1868]
无 damage      B=[ 812, 1005, 1178, 1264, 1463, 1567]  A=[ 511,  868,  947, 1176, 1526, 1617]
滚动一行       B=[1960, 2196, 2208, 2581, 3418, 7504]  A=[1002, 1589, 1781, 1946, 1948, 2094]
拖拽选区       B=[1120, 1297, 1443, 1649, 4531, 6034]  A=[ 734,  954, 1401, 1440, 1921, 3500]
```

两个样本量级分析之外的补充说明：单行 dirty 是打字态的稳态场景（每帧一次
光标覆盖写入），收益来自 O2（删除每帧 4×Arc 全量重建）叠加 O1；拖拽选区的
收益被 mouse-move 事件链开销摊薄，中位数下仍稳定改善。

## 回归

- 530 个测试全绿（525 原有 + 新增 5：选区平价 / 内存测量×4）。
- clippy 与基线分类清单一致，零新增。
- release 构建通过。
- 行缓存一致性校验（`DEEPTERM_VALIDATE_ROW_CACHE=1` debug 断言）保留，
  校验签名随 O1/O2 更新。

## 风险与权衡

- O1 的算术求交依赖 `SelectionRange::contains` 的区间语义（与 alacritty 0.26
  源码逐字核对）；若上游语义变更，平价测试会立即红。
- O2 改变了 paint 的数据来源（行缓存所有权在 prepaint→paint 之间归元素持有），
  该窗口内不可有其他路径访问 `view.row_render_cache`（gpui 元素帧内无并发，
  已确认）。
