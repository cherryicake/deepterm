# 实时 Markdown 编辑器性能与内存优化报告（2026-09-24）

针对 **md 实时编辑器**（`src/editor/markdown_live/`）打开较大文档时「内存暴涨、
滚动卡顿、打字卡顿」做的一轮优化。全部结论都有测量或测试支撑。

测量环境：macOS 25.4.0 arm64（Apple Silicon），`nightly` 工具链，
gpui rev `ac099b4` `#[gpui::bench]`（真实排版 + 无头 Metal 提交）。

复现：

```
cargo bench --bench markdown_live -- --warm-up-time 1 --measurement-time 2
cargo test  --lib markdown                    # 功能回归
cargo test  --lib typing_phase_breakdown -- --ignored --nocapture   # 阶段拆解
```

---

## 一、根因

渲染端**已经有行虚拟化**（`view.rs` 的 `virtual_window`，>200 group 时只建视口
元素），所以「元素构建」本身是 O(视口)。但虚拟化**之外**的工作全是 O(文档)，
虚拟化一点都没省掉；而且每次击键有 4~5 份全文拷贝。三类症状对应三组问题：

| 症状 | 根因 |
|---|---|
| 滚动卡顿 | 每个滚动 tick = 一次完整 `render`，而 render 里分组/校准桶/有序号/mermaid 扫描/可见性位图/`planned` 深拷贝都与视口无关，全是 O(文档) |
| 打字卡顿 | 每次击键：全量重新规划（classify + plan + 每行 14 个 `Vec<bool>`）、`auto_prettify_table` 无条件全量分类、`Change` 事件带全文、影子 `InputState` 全文重排 |
| 内存暴涨 | 撤销栈每步克隆整个 `Vec<String>`（上限 200 步 → 最坏 200×文档）；`planned` 每帧深拷贝；图片每帧同步读盘解码 |

代码里原本就留有线索：`markdown_element.rs` 的 `TODO(性能)：仍在 render
同步读文件`，以及 `docs/PERF_MEMORY_AUDIT_2026-09-12.md` 的 M1（撤销快照无界）、
P1（全量重算），`docs/PERF_2026-09-19.md` 明确记着「markdown P1 仍未实装」。

## 二、改动

### 2.1 渲染帧管线：把 O(文档) 从帧路径上摘掉

**`planned` 改 `Rc<Vec<PlannedRow>>`**（`view.rs`）。每帧 `planned_rows(...).to_vec()`
曾把整篇 plan（每行的 `visible: String` + `runs` + `segs` + `links`）深拷贝一遍，
包括 500ms 的光标闪烁帧。现在只做一次引用计数自增。

**新增 `PlanGeometry`（按 `text_version` 缓存）**。分组、校准桶、行范围、
行→group 归属、有序列表号、mermaid 块列表都是**纯文本函数**（不含光标/选区/
reveal），此前每帧重建。现在随文本变更重建一次，帧路径只读。

**可见性判定从位图改 O(1) 归属查询**。原实现每帧 `vec![false; rows.len()]` 再
把窗口内每个 group 的行标进去，还用 `rows.iter().position()` 扫光标行；现在
`group_of_row[pi] ∈ [lo, hi]` 一次比较，光标行单独处理。

**每帧遍历范围收敛到窗口**。`code_runs`（代码块高亮）、`paints`（行绘制）、
`find_marks`（查找高亮）、`display_numbers`（有序号）原本都从第 0 行扫到文档尾
（内部再按可见性跳过）。现在按 `window_rows(lo, hi)` 直接取行区间；有序号改查
几何缓存里的整表。

**虚拟窗口查找改二分**。前缀和上找窗口原本是线性扫描（每帧 O(group)）；改
`partition_point`。`virt_prefix` 用 `mem::swap` 复用上一帧的缓冲（原本每帧
`clone()` 整份 `Vec<f32>`），`all_vals` 去掉多余克隆。

**`LiveBuffer` 新增行起始偏移索引**。offset ↔ `Pos` 原本是 O(行数) 线性扫描。
搜索高亮要把**每个**匹配区间换算成行列，于是变成 O(匹配数 × 行数) —— 查找面板
开着时这是最大的隐藏热点。现在 O(log 行数)。

### 2.2 每键路径

**`auto_prettify_table` 加廉价门控**。此前每次击键都 `lines().to_vec()`（全量
克隆）+ `table_block_range`（内部无条件 `classify_document`），**哪怕文档里根本
没有表格**。现在先问缓存几何：缓存新鲜且无表格 group 直接返回；否则看光标所在
段落 run（前后到空行为止）里有没有 `|` —— 表格不可能跨空行，run 内无 `|` 就
一定不是表格。这是保守否定，命中表格时照常走完整路径。

**`inline::parse_with_refs` 加无触发字节快路径**。每行原本分配 14 个
`Vec<bool>`（长度 = 行长）再跑十个 pass。纯文本行（不含任何标记字节）现在直接
返回单个默认 span。触发字节集合由差分测试钉住：快慢两条路径逐字节比对。

**`table_refs` 缓存键去掉光标/选区**。分类是纯文本函数，方向键移动不再触发
全文重扫。

**mermaid 相关**。`MermaidKey` 的 `String` 改 `Arc<str>`（`body()` 每次调用不再
分配）；块源码随几何缓存，pass1 与渲染分支都不再逐帧 join；复制按钮改点击时
才拼文本。

**`Change` 事件不再带全文**。`LiveViewEvent::Change(String)` → `Change { version }`。
消费方需要文本时自己取。

**影子 `InputState` 同步防抖（250ms）**。live tab 渲染完全不读它（只有保存/
切标签页组/关闭确认读），而每次击键的 `set_text(全文)` 会重建 `Rope` 并整篇
重排软换行。现在这三条路径前 `flush_all_live_shadows` 强制落盘，保证可观测
行为不变；脏标记改用版本号 O(1) 对比（`LiveBuffer::is_dirty_fast`）。

**查找面板同步**。面板关着时完全跳过；开着时 120ms 防抖，跳转/替换前
`sync_search_now` 对齐，避免按过期偏移改写文本。

### 2.3 图片：后台加载 + 缓存

图片卡片原本在 render 里**同步**做 `fs::metadata` + `fs::read` + 解码
（SVG 走 `usvg`）+ `Image::from_bytes` 的字节哈希，**每帧每张可见图**重来一遍。
现在：

- 视图级缓存（键 = URL，值 = 加载中/成品/失败，含 `(mtime, len)` 指纹）；
- 未命中时只做一次 `metadata`（不读内容），随后 `cx.spawn` 到后台读盘解码，
  完成 `notify`；
- 文件 mtime/大小变化自动失效重载；文件不存在记 `Failed`，不再每帧探测。

安全门禁（扩展名白名单 / `..` 逃逸 / 远程 URL）抽成
`MarkdownElementBuilder::local_image_path`，同步（只读预览）与后台（实时编辑器）
两条路径共用同一套规则。

### 2.4 内存：撤销快照共享行文本

`EditorModel` 的撤销栈每步 `self.lines.clone()`（`Vec<String>`，全量文本），
上限 200 步 → 最坏 `200 × 文档字节`。改为 `Vec<Arc<String>>`：

- 快照只克隆**指针表**（每行一次引用计数自增）；
- 改动行走 `Arc::make_mut` 写时复制，只复制那一行。

保留内存从 `steps × 文档` 变为 `steps × 行数 × 8` + 实际改动行文本。
对散文（平均行长 ~50B）约 6× 改善，行长越大收益越高（长段落、CJK、
URL/base64 密集的文档更明显）。

## 三、测量

### 3.1 帧路径（`cargo bench --bench markdown_live`）

三档文档规模测同一操作，**斜率就是回归指标**。改动前后各测一次
（同一台机器、同一条命令、无其它构建在跑）：

| 场景 | 1k 行 | 5k 行 | 20k 行 | 结论 |
|---|---|---|---|---|
| 空转重绘（blink/闲置）· 前 | 0.73 ms | 1.21 ms | **2.56 ms** | 随规模线性 ↑ |
| 空转重绘 · **后** | 0.60 ms | 0.62 ms | **0.89 ms** | **近似常数** |
| 滚动一帧 · 前 | 1.09 ms | 1.16 ms | **2.54 ms** | 随规模线性 ↑ |
| 滚动一帧 · **后** | 0.60 ms | 0.63 ms | **0.89 ms** | **近似常数** |
| 单字符插入 · 前 | 1.36 ms | 3.72 ms | **13.24 ms** | 随规模线性 ↑ |
| 单字符插入 · **后** | 0.75 ms | 0.98 ms | **1.90 ms** | 7.0×，斜率大幅压平 |

**滚动/空转在 20k 行上的收益约 2.9×，且斜率归零**：1k 与 20k 同价（差异
在噪声内），这正是本轮的目标 —— 帧路径不再随文档增长。优化后 1k 行的读数
也低于优化前（滚动 1.09 → 0.60 ms），说明小文档同样受益、没有引入回归。

### 3.2 击键路径（增量规划）

击键延迟的主项是**全量重规划**（release 口径 20k 行：classify 3.6ms +
plan 15.3ms）。本轮把它改成增量：

**分类**（`classify_incremental`）。分类是前向状态机，`Classified` 按每
64 行存一个状态检查点；编辑时从最近检查点恢复、向前重算，**一旦运行态与
上次保存的同位状态完全相等就停止**，之后各行复用旧结果。收敛判据是精确
状态比较（`DocState::same_parse_state`），不是启发式。

**逐行 plan**（`plan_range` / `plan_one`）。`planned` 改为
`Rc<Vec<Rc<PlannedRow>>>`：重算一行只替换一个 `Rc`。脏行由 `EditorModel`
在改动点记账（`mark_dirty`：单行编辑记该行、换行记到行尾、整档替换/撤销/
重做记「未知」= 全量），view 只在窗口内做指针比较；文本改动会把区间加宽到
所在块 run（到空行为止；fence/math/frontmatter 自定界），因为分类有一行
lookahead 且围栏状态向后传播。

**几何缓存门控**。分组/校准桶/有序号/mermaid 块表只在输入真变了时重建
（块类型变化、`RowKind` 变化、或编辑落在 mermaid 块内）。

| 场景 | 1k 行 | 5k 行 | 20k 行 |
|---|---|---|---|
| 单字符插入 · 前 | 1.36 ms | 3.72 ms | 13.24 ms |
| 帧管线优化后 | 1.12 ms | 2.60 ms | 8.77 ms |
| **增量规划后** | **0.75 ms** | **0.98 ms** | **1.90 ms** |

各阶段实测（release，20k 行，`typing_phase_breakdown`）：
增量分类 **0.20 ms**（全量口径 3.6 ms）、refdefs 0.05 ms、reveal 集合
0.02 ms、单行 plan **2 µs**（全量口径 15.3 ms）、几何重建 0.7 ms
（仅在结构变化时发生）。

### 3.3 内存

`AllocObserver` 的 live-bytes 高水位（度量**保留**内存，非分配次数）：

| 场景 | 旧（全量快照） | 新（共享行文本） |
|---|---|---|
| 2000 行 × 56B 文档 + 200 步编辑 | ≈19.2 MB（推算口径） | **3.3 MB**（实测） |

测试 `undo_snapshots_share_line_text_instead_of_copying_it` 断言实测值低于
指针表口径的 2 倍、且低于旧口径的 1/4。另有
`snapshot_lines_are_isolated_from_later_edits` 防止写时复制被就地改写。

## 四、验证

- `cargo test --lib markdown`：**283 通过 0 失败**（含虚拟化、滚动稳定性、
  表格语义、IME、mermaid、showcase 全量回归）。
- 新增测试：
  - `inline::fast_path_matches_slow_path_exactly`：快/慢解析逐字节差分；
  - `inline::trigger_set_covers_every_marker_byte`：触发字节集合覆盖性；
  - `buffer::offset_index_matches_naive_scan`：偏移索引对拍朴素扫描（含编辑后）；
  - `model::undo_snapshots_share_line_text_instead_of_copying_it`：内存上界；
  - `model::snapshot_lines_are_isolated_from_later_edits`：写时复制隔离；
  - `view::perf_diagnostics::typing_phase_breakdown`（`#[ignore]`）：阶段拆解；
  - `view::incremental_plan_tests::incremental_matches_full_plan`：随机编辑流下
    增量 plan 与全量 plan 逐字段相等，**并同时比对几何**
    （ginfo / group_of_row / display_numbers / has_table / mermaid 块）；
  - `reveal::incremental_classify_tests::*`：增量分类等价性、重算窗口不随
    文档规模增长、未闭合围栏必须让尾巴失效（防「假收敛」）。
- `cargo test --lib`（全库）1402 通过；唯一失败是终端 footprint 测试在并发下
  的既有抖动（单线程复跑通过，该文件注释已说明其进程级读数的并发敏感性）。

## 五、未做 / 后续可做

按收益排序，都是本轮**刻意留出**的独立改动：

1. **`RowPlan.visible` 改 `SharedString`**。每帧每行 `SharedString::from(
   plan.visible.clone())` 是一次字符串拷贝；改 `SharedString` 后 O(1)。
2. **几何增量重建**。目前几何只在「输入变了」时全量重建（0.7 ms / 20k 行，
   只在结构变化时发生）。按窗口 splice 分组表可把这笔也降下来，但收益已经
   不大（普通段落编辑根本不触发）。
3. **高亮缓存键改 `(text_version, block_range)`**。现在键是
   `(language, 整块内容)`，块内每次击键都产生新键；且命中时仍克隆
   `Vec<Vec<TextRun>>`。改版本号 + `Arc` 共享可再省一笔。
4. **手写虚拟化换 `gpui::list` + `ListState`**。SumTree 测高、二分窗口、
   滚动锚定都是现成的，能顺带解决注释里反复提到的「底部回滚上下抖动」
   （现有实现在 `virtual_window` 里手工补偿 prefix 漂移）。
5. **每帧预算**（gpui-flowtext 的 8ms budget 思路）：规划/高亮超预算分帧补齐，
   保证极端文档下不掉帧。
6. **大文档降级开关**（VS Code `largeFileOptimizations` / Typora 的
   `MAX_FILE_SIZE` 同款）：超过阈值关闭 mermaid/图片/表格网格，或整体走
   源码渲染 + 顶部提示。当前只有「>20MB 拒绝打开」这一道门。
